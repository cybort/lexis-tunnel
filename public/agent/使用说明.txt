词隙客户端 3.0.0（协议 lexis-hctr2-rans-v3）

这一版和 1.8.0 及更早的所有版本都对不上，两端必须同时升级到 3.0.0。帧改成 HCTR2 宽块置换加语料词编码，握手的临时密钥从 P-256 换成 X25519（Elligator2 编码），长期身份密钥仍是 P-256，原来的身份文件和口令不用换。新旧进程连握手都过不了：闸门对旧版 hello 一律静默丢弃，等到握手超时才断开，不会回任何报错。线上没有版本字节（加了就是指纹），所以版本不一致只表现为“握手超时”。时钟窗仍是 300 秒、左右各 120 秒。

转发正文和控制台是同一套词表。两端用长期公钥做 ECDH，会话密钥用 Argon2id。常驻进程用自己配置里的内存、迭代和并行，不采用对端报上来的更高开销。伪造问候要先过握手口令。口令写在 link.token，两端相同，至少 16 个字符。它在 Argon2 之前校验，不是词表密钥。问候的时间窗是 300 秒。时钟慢或快时，上一窗只在新窗的前 120 秒还接受，下一窗只在当前窗的最后 120 秒接受。更远的窗仍然拒绝。过期的问候和同一个时间窗里的重放都会被拒绝。同一个节点或同一个地址在一个时间窗里不能占满全部名额。派生密钥的线程如果出错或超时，下一次握手会再拉起一个。

计数器、密钥流和秘密词表把明文写成散文。明文第一个字节决定是原文还是 zstd。帧尾 16 字节是随机数，不是 HMAC(会话密钥, 正文)。拿记录下来的帧去重算旧校验，真密钥和猜错的密钥都对不上，比对结果看不出差别。握手确认改成公开的记录标记，不再混入会话密钥。记下问候再去试长期私钥，不能靠这段确认来判断猜对没有。只复制了公钥的人可以重算这个标记，所以它也不证明两边算出了同一把会话密钥；对不上的时候，数据帧拆不开，而不是确认标记报密钥不对。下面这些仍然能让猜中的人自己核对，这一版没有拿掉：词表仍由会话密钥和当前时间窗导出，词能落进这份词表，就说明密钥是对的；正文长度在减掉密钥流之后仍是结构；计数器掩码仍是 HMAC(密钥, 时间窗)，拆开以后计数器很小，也能对上。握手口令的校验仍然能确认口令，这是故意的。蜜文打开时，词不在词表里、正文结构不对、或者计数器回放，都不报错，落成这把密钥和当前时间窗自己的一句话，也不拆会话。词表格式不变。换一把私钥，或换一个时间窗，词就不同；两把错误私钥之间也不会撞成同一份词表。蜜文关掉时，回放仍会拆掉这条会话。拆不开的数据帧不会把整条会话拆掉。初始私钥可以封成系数：任意一句口令都解开一把合法私钥，再叠上时间窗得到那份词表，程序里没有「这句口令是备用」的判断。封面若已写成系数，拆开时每一把密钥走同一条求值。备用明文和真私钥写在同一条求值里。计数器接近上限，或时间窗换了，会话里会换一把密钥。换钥载荷是 16 字节随机数再加 4 字节时间窗。心跳如果连续三个周期没有收到对端，这条会话会关掉。

外层只负责把头和协议走完，方便过 CDN：
- tcp：一行一句词表
- tls：同一句词表走在 TLS 应用数据里。正式部署请换成自己的证书，并打开校验。tlsVerify 为 false 时进程会警告
- ws / wss：一条 WebSocket 文本消息就是一句词表，路径默认 /lexis。CDN 若自己终结 TLS，源站听 ws，客户端连 wss，并填 CDN 的主机名

身份写在 identity。peers 里放要加入的节点，公钥必须对上。没有封存时，导出的配置带本机私钥，不要外传。封存以后，配置和侧车都不写私钥标量，也不写系数。系数只在旁边的 lexis.seal.json，里面没有公钥、没有指纹。口令放在环境变量 LEXIS_PASSPHRASE，或同目录的 lexis.passphrase。常驻进程用同一条求值解开，不会拿结果去对配置里的公钥，也不会把标量写回磁盘。口令不对会得到另一把合法私钥，对端会说绑定不一致，不会说口令错误。封存的 Argon2id 是 65536 KiB、3 次迭代，不吃握手那一档 16384 KiB 的上限。同时拿到封存文件和这份公钥的人，仍可以离线试口令，只是更慢。改名单不用重启：摘掉的节点，会话会关掉。

一条会话上可以开多路。打开命令是 `tcp 主机 端口`、`udp 主机 端口`、`relay 节点 tcp 主机 端口`，或 `expose 服务名`。中继默认关闭，出口也默认关闭。想让某个节点借本机中继，把 relay 设为 true。想让它把本机当出口，把 exit 设为 true。targets 写了就只允许那些目标，空着不限制。暴露不能经中继打开。跳数超过 4 就拒绝。把流送回上一跳也会拒绝。某一路读得慢，只堵住这一路，不会拆掉整条会话。本机这一侧也会停下来等信用，不会无限读进内存。

NAT 后面的机器用边缘角色连出去。配置里的 role 必须写成 edge 或 gate。缺了角色不再当成边缘，进程拒绝启动，也只有 edge 会去保持到对端的连接。exposes 里写服务名、本机 host:port，以及允许访问的节点名或编号。公网闸门用 reverses 在本地听一个端口，从已经连进来的会话反向打开同名服务。也可以访问「节点名:服务名」。没有那条会话时，会说没有来自该节点的会话。没有打开 link.allowLan 时，反向入口即使写成 0.0.0.0 也只绑回环，并且计入连接数上限。断线后边缘角色会退避重连。状态页默认只绑回环，这时 /metrics 和页面不需要口令。statusHost 离开回环时，要有 statusToken，请求带 Authorization: Bearer 或 ?token=。口令是空的又没有允许局域网，状态页改绑回环。/health 一直公开，而且只回答是否活着。

要听 tls 或 wss，把自己的证书和私钥放到程序旁边，命名为 lexis-tls.crt 和 lexis-tls.key。两边都没有时，如果本机有 openssl，进程会在旁边生成一把，只给这一台用，不要把那把私钥分发出去。

SOCKS 接受 CONNECT 和 UDP ASSOCIATE，UDP 可以是 IPv6。http 入站是 HTTP 代理，支持 CONNECT 和绝对地址的普通请求，认证跟 SOCKS 用同一对用户名密码。同一条连接上的每一个请求都会单独重写：代理认证不会带到目标，Host 必须和绝对地址一致，Content-Length 和 Transfer-Encoding 写在一起会直接拒绝，不会转发出去。HEAD、204、304 没有正文，不会干等到空闲超时。1xx 会转给客户端，然后继续读真正的响应。没有长度、也不是分块、一直读到连接关闭的响应，末尾不足 16 KiB 的那段也会送完。socksAuth 的用户名和密码都填了才认证，留空就不认证。

固定端口：进程监听配置里的端口。SOCKS 和 HTTP 给本机程序当代理；TCP 入站按目标转发；tunnel 入站做词表握手，然后接受上面的打开命令。
系统接管：进程仍常驻，并写出平台脚本。Linux 在有 root 和 iptables 时写 redirect 或 tproxy。redirect 的 OUTPUT 会把本机程序转回透明端口；本进程的每一条 TCP 出站，包括连对端的隧道外层，先打 fwmark，规则碰到这个标记就放行。tproxy 同时写 PREROUTING 和 OUTPUT，TCP 和 UDP 都写。旁路标记是配置里的 mark，转进本机监听的是另一个标记，两个不能用同一个。私网、运营商级 NAT、组播和对端的 IPv4 地址不接管。IPv6 这一版还没有单独的监听。虚拟网卡 lexis0 的默认路由只接公网；私网和对端地址仍走原来的路由。用户态栈仍是词隙自己的，不是 gVisor：段长 1200，未确认的段可以重发，乱序先留一段，对端窗口是 0 时停发。系统接管且 linux.dnsRedirect 不是 false 时，虚拟网卡、本机包通道和透明 UDP 上的 53 端口在进程里回答。A 记录给 198.18.0.0/15 里的一个假地址，AAAA 回空的 NOERROR。假地址只存在于本机，拨号前映射回域名，这样 GEOSITE 仍看得到名字，也绝不会去连 198.18。标记由本机模块设置，连接由 Node 发起，不再在主线程里同步解析和等待。没有 root、没有 iptables，或内核拒绝 IP_TRANSPARENT、SO_MARK、TUN 时，规则只留在文件里，流量不会被真正接管。这一版没有在具备这些权限的机器上证明 redirect、tproxy 或虚拟网卡已经接住流量。Windows 的 portproxy 只绑 127.0.0.1。WinDivert 只有 windivert-redirect.c，驱动和 exe 不在包里，选了也不会改系统流量。Android 写出 vpn-session.json，绕过私网、运营商级 NAT、组播和对端地址，包通道在 127.0.0.1:17891，旁边有 LexisVpnService.kt 源码。Termux 不能弹出系统 VPN，也没有编译好的安装包。

SOCKS、HTTP 和固定转发默认只绑 127.0.0.1。只有 link.allowLan 为 true 时才按配置里的地址监听。反向入口同样受这道限制。隧道入口可以听更宽的地址。
出口拨号前会先解析域名。回环、内网、链路本地、运营商级 NAT 和文档地址默认拒绝。egress.allow 一行一个主机、主机:端口或 IPv4 网段，用来单独放行。这道拦截不作用于你本机 SOCKS 的直连和绕行，也不作用于你自己暴露的本机服务。公网的 22、80、443 不单独封禁。握手超时、拨号超时和同时握手数在 link.handshakeMs、link.dialMs、link.maxHandshakes。

程序名：接入、绕行或拒绝。Linux 从 /proc 认进程，Windows 用当前连接的进程名，Android 上认不到进程时规则仍留在配置里。
路由：DOMAIN、DOMAIN-SUFFIX、IP-CIDR、GEOSITE、GEOIP、PROCESS-NAME、MATCH。内置 geosite/geoip 是一份小样。完整库把文本 URL 填进配置，客户端启动时拉取。域名还不会先解析再套 IP 规则。没有单独的 DNS 入站。假地址只在系统接管里回答 53 端口，见上面。

安装：
- Windows：在解压目录里运行 install.ps1。登录后任务 LexisAgent 会把进程拉起。证书只有你自己放进来时才会复制。配置、封存、口令和 TLS 私钥会收成当前用户可读写、别人不可读。
- Linux：sh install.sh。有 systemd 就装用户服务，没有就 nohup。上述文件设为 600。
- Android：在 Termux 里 sh install.sh。同样把这些文件收成仅本人可读。
常驻进程启动时会再收一次。手动覆盖之后重启进程。

状态页默认是 http://127.0.0.1:17890/ ，同端口还有 /health 和 /metrics。
镜像说明在 Dockerfile，样例配置的口令是空的，进程会拒绝启动，要换成至少 16 个字符再跑。
控制台导出的 JSON 覆盖 lexis.config.json。名单和公钥变化会自己重读，旧会话会断开。两端都要把对方公钥放进 peers，并写同一个至少 16 个字符的握手口令。要让对方从本机出去，把那个节点的 exit 打开。没有做过连续 24 小时的浸泡。
